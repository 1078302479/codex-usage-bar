# 官方侧栏本地补丁（实验阶段）

当前弹框复用官方额度按钮的原生菜单组件，采用 `surface="menu"` 和 `size="compact"`，宽度随内容调整，上限为 400 个逻辑像素，同时受可用屏幕宽度约束。重置时间与倒计时按完整片段排版，时区在标题处统一标示。悬停由原生 `openOnHover` 处理，文字、进度条和分隔线随客户端主题切换。

客户端额度响应支持 `rate_limit_reset_credits.available_count` 可用重置卡摘要。逐张卡片由只读 `GET /wham/rate-limit-reset-credits` 获取，客户端使用 `credits`、`available_count`，卡片明细使用 `id`、`status`、`expires_at`、`title` 等字段。补丁通过语法树定位该 GET 对应的原生查询 Hook 和分包，首次打开弹框时加载它，复用客户端账号上下文和缓存逻辑。消费接口不接入展示组件。

重置卡区域展示可用数量、未来 72 小时内到期数量、最近到期倒计时与默认展开的逐卡明细。「使用」通过客户端路由进入设置并定位到「使用限额重置」。账号变化时重建查询视图，加载和失败期间保留额度摘要中的数量并显示状态。

## 自动适配更新

生成流程使用 Acorn 解析本机安装的 JavaScript 语法树，自动搜索导出的 `AmbientUsageRailMenu`，定位模块作用域中的 React、JSX、原生菜单与 `usage` 绑定。文件名、压缩变量名和应用版本号改变时，只要这些结构约束仍成立，就可以生成对应版本补丁。

新增依赖后，先在 `windows` 目录运行 `pnpm install --frozen-lockfile`。只读兼容性分析命令为：

```powershell
node windows/patch/manage.mjs analyze '<原客户端app目录>'
```

`stage` 自动使用分析结果，逐次记录该次资源指纹和客户端版本。客户端在分析后变化会中止生成，应用时仍校验原文件与备份。旧版固定指纹补丁清单继续支持核验与还原。

覆盖范围包括客户端资源重打包、文件名变化、压缩变量改名和保留相同组件结构的版本升级。出现多个候选、组件导出更名、返回结构变化、额度字段更名、依赖移入其他作用域或可执行文件完整性格式变化时会停止，需要人工检查。

此流程分析本机已安装更新的资源，不执行客户端源码。更新检测、自动下载新客户端、自动切换测试副本和真实界面回归检测尚未实现。生成补丁仍会改变 EXE 签名，自动识别界面结构无法解决签名问题。

已在客户端 `26.1103.31037` 的测试副本上验证侧栏位置、原生菜单和重置卡明细。组件读取官方按钮现有的 `usage` 属性，重置卡明细通过客户端自身的只读查询加载。测试副本安装方式见 [Windows 安装说明](../README.md)。

本机测试入口（先保存并退出当前桌面客户端，脚本不会替你终止进程）：

```powershell
powershell -NoProfile -File windows/patch/Start-SidebarTest.ps1
```

脚本在启动前再次验证补丁文件。不复制用户数据/认证目录，不自动添加开机启动或创建系统级安装。若启动失败或系统拒绝修改签名的 EXE，保留原安装继续使用并收集具体错误，不更改系统安全策略。

## 这版客户端的实际限制

本机 Store 包是 `OpenAI.Codex_26.1103.3517.0_x64__2p2nqsd0c76g0`，包内应用版本为 `26.1103.31037`，两种版本号不同。

`ChatGPT.exe` 内嵌了 `resources/app.asar` 的头部 SHA256 校验值。修改界面资源后，必须同步更新此记录，否则不是可用的匹配资源。工具保留完整性校验本身，不关闭校验开关。

但更新这个记录会改变 EXE，导致原 Authenticode 签名失效。本机已实测：原文件签名 `Valid`，离线补丁副本 `HashMismatch`。不能把它当成官方签名插件发布或覆盖安装。

激活工具拒绝修改 WindowsApps 管理的安装目录，仅在用户目录下的完整测试副本上应用补丁。系统若阻止副本启动，请继续使用官方安装版。

## 文件结构

- `asar.mjs`：只读 ASAR 解析及入口完整性验证。
- `inspect.mjs`：只读定位导航栏额度候选模块。
- `sidebar-runtime.mjs`：纯 UI 与 GUI 原生额度模型。
- `auto-adapter.mjs`：语法树定位与结构检查，按当前资源生成插入位置。
- `profile.mjs`：保留旧版本固定指纹转换函数。
- `archive-build.mjs`：流式生成资源副本，更新修改项的 SHA256 与分块校验，同时保留其余资源。
- `manage.mjs`：生成、预检、激活、备份和还原。

生成文件保存在仓库忽略的 `.local/` 下，包含本机客户端资源，不应提交到 Git 或发布。

## 开发命令

在仓库根目录执行，路径参数中的 `app` 是包含 `ChatGPT.exe` 的目录：

```powershell
# 只读检查
node windows/patch/inspect.mjs '<原客户端app目录>/resources/app.asar'

# 生成离线副本。输出目录必须尚不存在，上级目录需存在。
node windows/patch/manage.mjs stage '<原客户端app目录>' '.local/windows-sidebar-v1'

# 验证原客户端仍与补丁兼容，且补丁副本未发生变化
node windows/patch/manage.mjs check '<原客户端app目录>' '.local/windows-sidebar-v1'

# 以下命令仅用于完整的用户目录测试副本，不能以 WindowsApps 安装目录为目标。
# 先保存工作并关闭测试副本，工具也会检查目标路径下的进程。
node windows/patch/manage.mjs apply '<完整测试副本app目录>' '.local/windows-sidebar-v1'
node windows/patch/manage.mjs restore '<完整测试副本app目录>' '.local/windows-sidebar-v1'
```

`.local/windows-sidebar-v1` 仅包含两份修改文件与清单。使用安装脚本可生成包含原应用 DLL、资源及 unpacked 文件的完整测试副本。

激活前逐文件检查原始 SHA256，备份到测试副本的 `.usagebar-backup/<profile>/`。同名备份存在时停止，不覆盖。备份完成并再次核验后才替换文件，第二个文件替换失败时回滚第一个。还原时要求当前文件仍是该补丁版本，避免覆盖更新后的客户端。备份与原补丁目录都应保留。

若写入期间程序被强行结束，可能留下 `.usagebar-patch.lock` 和部分文件，工具会拒绝继续。此时先人工核对备份、当前文件和清单，不应盲目删除锁重试；普通异常已覆盖自动回滚，掉电恢复尚未提供自动修复。

## 重新适配条件

应用已有补丁时，完整目标资源或应用文件改变会拒绝覆盖，需要针对新版本重新运行 `analyze` 和 `stage`。结构兼容时自动生成，结构检查不通过时再人工适配。工具暂不自动跟随更新，也不能保证所有未来版本都兼容。

## 验证范围

自动测试覆盖未知/零额度、周额度独占方案、重置边界、旧值标记、指纹不匹配、锚点重复、ASAR 资源保留和哈希、可执行文件定点校验更新、备份还原、部分失败回滚及更新后的文件拒绝覆盖。

其他客户端版本、主题和显示缩放组合仍需实机验证。
