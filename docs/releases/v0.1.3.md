# CodexUsageBar v0.1.3

连接自恢复与更新状态 / Connection recovery and update status

## 中文

- 网络请求失败、服务暂不可用、超时和自有子进程断开后自动重试，间隔依次为 5、15、30、60、120、300 秒，之后保持最长 5 分钟间隔。
- 检测到网络从不可用变为可用后合并提前核验；网络可达性仅作恢复提示，不代表服务已经恢复。
- 高频日志、通知、定时刷新与打开面板不绕过退避。手动刷新可立即重试；需要登录、更新 Codex、选择程序或处理权限时停止自动重试。
- 显示查询中、已核验、数据已过期、重置待确认、网络请求失败、超时、连接断开、需要登录、版本不兼容等状态；显示最近成功核验及下次重试时间，缓存单独标记。需用户处理时可直接打开连接设置。
- 休眠取消请求、重试和时钟；唤醒合并核验。账号/程序变化和休眠前的迟到结果不能覆盖新连接数据，旧请求不能结束新子进程。
- 官方 Token 活动接口不支持时，只提示活动不可用，不影响额度核验。
- 兼容连接初始化期间的账号通知：在原连接上重新核验，避免误触发反复重连；账号通知前的请求结果会被丢弃。

验证覆盖核心断言、热力图、日志候选、恢复协调与状态回归，以及真实 stdio 模拟程序中的网络错误恢复、自有子进程退出重连、请求超时、请求中模拟休眠/唤醒与退出清理。窗口生命周期回归和真实账号只读查询亦已验证。尚未完成真实断网、整机休眠唤醒与至少 8 小时连续运行验收。

## English

- Recover automatically from network/service failures, deadlines, and owned child-process disconnections with 5/15/30/60/120/300-second retry backoff, capped at five minutes.
- Coalesce an earlier query on a network-return hint; path availability is not treated as proof of service health.
- Prevent automatic events, polling, and panel opening from bypassing backoff. Explicit refresh can retry immediately. Login, configuration, permission, and compatibility problems require user action.
- Show validation, stale-data, reset-pending, network, timeout, disconnection, login, and compatibility states, last successful validation, and next retry time. Label unverified caches separately and provide a direct connection-settings action.
- Cancel requests, retries, and timers on sleep, and coalesce wake validation. Isolate old results and process generations across sleep, account, and configuration changes.
- Keep quota validation available when optional Token activity is unsupported.
- Revalidate account notifications on the same connection, including those emitted during initialization, instead of creating a restart loop; discard pre-notification results.

Validation includes coordinator/state regressions and real-stdio fixtures for network errors, child replacement, deadlines, simulated in-flight sleep/wake, and cleanup, plus window lifecycle checks and a real-account read. Physical sleep/wake, actual network interruption, and eight-hour uptime remain unverified.
